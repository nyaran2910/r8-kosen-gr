# 設計上の決定

以下は会話と現行仕様に基づく方針。未実装のものも含むため、実装状況はソースで確認する。

- 原本から知識要素と試験傾向の構造化データを作成し、原本そのものを問題DBへ完全保存しない。出題用 `problems` は自作・生成した問題。試験は教科まで区別し、問題・出題・評価・復習は大問単位（`docs/backend/db.md`、`docs/common/requirements.md`）。
- 知識コストは大学の出題レベルを表す構想で、算出方法や尺度は未決定。未設定はNULLであり0ではない（`docs/backend/db.md`）。
- 知識と試験ごとの問題形式の理解度は1〜5。未評価は行がない状態で、初回のみ3を基準にする。知識は「わかった」+1、「わからない」−1。形式は完璧+2、正解+1、不正解・あきらめたは各−1。上下限で丸める（`docs/backend/db.md`）。
- すべての使用知識と問題全体の評価を一度に確定し、履歴・現在の理解度・復習予定を保存する。同じ評価の再送は二重更新しない。初版の復習日時は確定から72時間後とし、将来の忘却曲線に向けて計算処理を出題候補の選択から分ける（`docs/common/api.md`、`docs/backend/db.md`、`docs/common/requirements.md`）。
- 一人のユーザーが再開できる演習は予約段階を含め1件。画面表示による開始時刻と初回の解答閲覧時刻を維持する。未確定終了は評価せず、再開できない。評価下書きは同一タブ内で保持し、ログアウト・確定・終了時に消す方針（`docs/backend/db.md`、`docs/common/attempt-recording.md`）。
- 初版はWeb・API・DBをローカル起動し、Googleログインを使用する。認証はFastAPI側。アカウント削除時はGoogleの紐付けを除去し、内部IDと学習データは保持する。将来のAI学習利用は可能性であり、実装済みの使用ではない（`docs/common/requirements.md`、`apps/api/src/api/auth.py`）。
