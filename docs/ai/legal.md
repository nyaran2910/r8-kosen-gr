## 公表・記録についての決定（2026-10-09）

アプリでは必要な表示に絞り、内部には実際の出典と処理方法を記録し、研究発表では必要な範囲を正確に説明する。すべての参照資料をアプリ上で一律に列挙する運用にはしない。引用や個別利用条件による表示義務は別途確認する。

出典を外部に表示しないことを、独自に作成したという虚偽の説明に置き換えない。発表する部分は特に丁寧に根拠・再現性を確認するが、発表しない部分の取得・処理の確認も省略しない。

ユーザーは抽象的なDBから参照元を特定する難しさを指摘した。これは適法性の根拠や「発覚しない」という保証として採用したものではない。上記の公表範囲と内部記録の方針を合意内容として扱う。

内部記録には、資料の名称・実際の取得元・取得日・版・解答解説の作成方法・利用条件・抽出方法・レビュー結果を残す。未確認は未確認と記載する。「内部記録」はアクセス範囲を指し、`docs/ai/` に置くだけで非公開になるわけではない。公開リポジトリに個別の内部記録を置く場合は公開範囲を確認する。

# 過去問の解析・抽出・問題生成に関する法務メモ

調査日：2026-10-09。日本の著作権を中心とする初期検討。東北大学工学部編入試験の公式掲載元と利用条件の記載を確認した。手元の資料の取得経路と、今回の利用に対する許諾の有無は未確認。以下の比較は、転載・配信の許諾がない場合を前提にした設計上の評価であり、適法性の確定ではない。

## 現時点の判断

**ユーザーが示した「原本から知識要素・大まかな出題傾向だけを抽出する案」の方が、以前の「原本の問題文・解答・解説をキャッシュして出題する案」より著作権リスクを抑えやすい。** 原本の表現を学習者に提供する工程を減らせるためである。これは下記の文化庁資料を、このアプリの設計に当てはめた評価。

以前の提案では、解析資料としての利用と、教材としての転載・配信を十分に区別していなかった。最新のDB案はユーザーの方針に合わせて修正済みなので、現在の両案にはその違いはない。

| 比較点 | ユーザーの案 | 以前の提案 |
| --- | --- | --- |
| 原本 | 解析元として利用 | 解析元に加え、出題用にも保存 |
| アプリDB | 一般的な知識・ジャンル・形式・傾向 | 原本の問題文・解答・解説も保存 |
| 学習者への提供 | 抽出した一般的な説明、自作・生成問題 | 原本の問題をそのまま提供 |
| 主な確認事項 | 解析時の利用条件、抽出・生成結果に原本の表現が残らないか | 左記に加えて原本の複製・配信の根拠 |
| 相対的な評価 | リスクを抑えやすい | 許諾なしでは確認すべき範囲が広い |

必要な許諾を得た原本を契約の範囲内で保存・配信する方法もあり得る。「保存する方法は常に違法」という比較ではない。

## 1. 知識と問題の表現を区別する

著作権は創作的な表現を保護する。事実、アイデア、数学的概念それ自体は保護対象ではない。一方、個別の問題文・図・解説に創作的表現があれば保護され得る。数学の問題がすべて保護対象になる、またはすべて対象外になるとは判断しない。[文化庁「AIと著作権に関する考え方について」4〜5頁](https://www.bunka.go.jp/seisaku/bunkashingikai/chosakuken/pdf/94037901_01.pdf)

このアプリでは、次のように抽出の粒度を判断する。

| 抽出候補 | 設計上の扱い |
| --- | --- |
| 「固有値」「対角化」「線形代数」 | 一般的な概念・分類として扱う |
| 「計算中心」「記述回答」「複数の小問からなる大問」 | 大まかな形式として扱う |
| 「確認した資料では行列の問題が出ている」 | 出典・調査範囲を付けた観察結果として扱う |
| 固有値の一般的な説明 | 自分の表現と独自の例で作成する |
| 原本の特徴的な文章・図・解説 | 抽出定義に転載しない方針 |
| 原本の条件・数値・小問の誘導を詳細に保持したデータ | 原本を再現できる可能性があるため、抽象化を見直す |

これはレビューの目安であって、数値や設問順序それ自体が常に保護されるという意味ではない。JSON化、Markdown化、言い換え、数字の変更だけで適法になるとは扱わない。

## 2. 原本を解析する工程にも確認が必要

著作権法30条の4は、非享受目的の利用を必要な限度で認める規定である。元の創作的表現を出力する目的が併存する場合や、著作権者の利益を不当に害する場合は適用が問題となる。原本をDBに残すかどうかだけでは決まらない。[文化庁「AIと著作権に関する考え方について」19〜23頁](https://www.bunka.go.jp/seisaku/bunkashingikai/chosakuken/pdf/94037901_01.pdf)

文化庁のRAGに関するFAQも、元の創作的表現を出力に含めない仕様では、入力データ収集時の複製が30条の4で認められる可能性を説明している。原本の表現を回答として提供する目的の仕様とは区別される。[文化庁FAQ 6－⑲](https://www.bunka.go.jp/seisaku/bunka_gyosei/kibankyoka/faq/index.html)

したがって、今回の「知識・大まかな傾向を抽出する」設計は、この整理と整合しやすい。ただし、実際の抽出指示・保存結果・運用についての確認が必要。

原本のダウンロード、OCR、作業ファイルへの保存、外部AIサービスへの送信には、それぞれ複製等の検討が生じる。処理後に原本を消すことだけで、処理時の利用の根拠が不要になるわけではない。外部サービスの保存期間・再利用条件・処理場所は、サービス選定時に確認する事項として残す。

## 3. 過去問の再配布を試験の例外で説明しない

36条の試験問題に関する例外は、試験・検定のための利用を対象とする。文化庁は、試験後の冊子配布やウェブ掲載は対象外と説明している。このアプリで過去問を反復学習用に配信することを、入試で使用されたという理由だけで正当化しない。[文化庁「著作権テキスト」掲載頁81](https://www.bunka.go.jp/seisaku/chosakuken/seidokaisetsu/pdf/94388701_01.pdf)

また、卒業研究、教育目的、非営利、ログイン必須という事情だけで、一般向けアプリでの転載・配信を適法と判断しない。学校の授業利用には35条などの個別要件があり、このアプリがそれを満たすかは別の問題である。[同テキスト・学校等の教育機関における利用](https://www.bunka.go.jp/seisaku/chosakuken/seidokaisetsu/pdf/94388701_01.pdf)

## 4. 生成問題の確認は別工程にする

原本の解析が許されても、出力した問題の利用まで一括して許されるわけではない。生成物については、既存著作物の創作的表現との類似性と依拠性が問題になる。[文化庁「AIと著作権に関する考え方について」生成・利用段階](https://www.bunka.go.jp/seisaku/bunkashingikai/chosakuken/pdf/94037901_01.pdf)

本アプリの実装方針案：

1. 原本を読む抽出処理と、学習者用の問題を作る生成処理を分ける。
2. 抽出処理には「一般的な知識・大まかな傾向を取り出す」という目的を明示する。
3. 抽出候補を確認し、原本の文章・図や具体的な問題を再現する詳細を定義から除く。
4. 生成処理のコンテキストには、レビュー済みの知識・形式・傾向を渡す。
5. 生成した問題は、文章・図・条件設定・小問の誘導に原本の特徴的な表現が残っていないか確認する。文字列一致だけで判断しない。
6. 初版のキャッシュには確認済みの自作・生成問題を入れる。

この分離はリスクを減らすための設計であり、原本を生成時に渡さなければ必ず安全になるという保証ではない。

## 5. 原本ファイルの公開は独立した問題

アプリDBへ原文を保存しなくても、原本を含むGitリポジトリや静的配信先を公開すれば、原本の配布について別途確認が必要になる。解析用に保持することと、誰でも取得できるようにすることは区別する。[文化庁「AIと著作権に関する考え方について」5頁・利用行為ごとの権利](https://www.bunka.go.jp/seisaku/bunkashingikai/chosakuken/pdf/94037901_01.pdf)

`assets/sources/東北大学過去問/` の既存資料については、取得元・権利関係・公開状態の調査をまだ終えていない。このメモの作成では原本の削除や公開設定変更を行わない。出典URLを記録することと、転載許諾があることも区別する。

### 利用条件には確認が必要な点がある

- 成果物の公表から1か月以内に利用報告をする。改訂・再編集時には報告が再度必要となる場合がある。
- 東北大学の問題からの引用であることを明示する。
- 改変した場合はその旨を、解答例を載せる場合は大学が公表したものではない旨を明示する。
- 第三者に著作権がある部分については、利用者が権利処理を行う。
- 自主学習や一定の教育機関の教職員による教育利用には報告不要の例外がある。このアプリが該当するとは未判断。

**この緩和方針が工学部の編入試験にも適用されるか、外部AIへの入力まで含むかは未確認。** 文書の題名は広いが、工学部の注意書きとの関係を明記していないため、本アプリへの包括的な許諾として扱わない。

また、大学の許諾条件と、著作権法30条の4などによる利用の可否は別の検討。禁止表示があるだけで情報解析が必ず違法になるとも、解析目的であれば表示や契約条件を無視してよいとも判断しない。法定の例外の適用、実際の取得時に合意した条件、処理内容を確認する。

### この調査を踏まえた方針

原本から一般的な知識・大まかな傾向を抽出し、学習者には独自の説明と自作・生成問題を提供する設計を維持する。今回見つかった緩和方針だけを理由に、原本の公開やアプリ配信を許可済みとは扱わない。

取得経路を確認した後、必要に応じて工学部教務課入学試験係に次を問い合わせる。以下は確認事項の案であり、問い合わせは送信していない。窓口は[工学部の公式ページ](https://www.eng.tohoku.ac.jp/admission/ugrad/adm-hen.html)に掲載されている。

1. 2025年7月1日付の二次利用方針は、令和7・8年度の工学部編入数学にも適用されるか。
2. 問題を公開せず、卒業研究で知識・形式・大まかな傾向を構造化して公開する利用に、大学の手続きが必要か。
3. 解析のために外部AIサービスへ問題を入力する場合に、追加の条件や手続きがあるか。問い合わせ時にはサービス名・保存・再利用条件も示す。
4. 抽出結果や独自の生成問題だけを公開する場合、利用報告・出典表示の対象となるか。

## 原本の保持と直接抽出の再確認（2026-10-09）

原本ファイル → 知識要素・問題傾向の構造化データ → レビュー → 定義テーブルへ登録。原本の完全な内容は原本ファイルで十分とし、全文・解答・解説を丸ごとDB化する工程は設けない。抽出データと自作・生成問題のキャッシュを区別する。問題傾向は現行のジャンル・形式・試験との関連で扱い、専用テーブルの新設は未決定。原本の公開・利用条件が許可済みになったという意味ではない。
