# 技術設定の詳細案

[概要](../common/runtime-settings.md) の描画・画像・通信・鍵配置の設定はユーザー確認済み。コード・環境構築・依存追加・鍵作成は行わない。

## 描画

react-markdownを本文表示に使用し、remark-gfmで表など、remark-mathとrehype-katexでTeX数式を描画する提案。KaTeXのtrustはfalse、生HTMLを有効にするrehype-rawは追加しない。許可するURLは内部知識・配信画像・通常のhttpsリンクに限定する。独自urlTransformで安全な既定動作を無効にしない。リンク・画像・表・数式は共通描画部品でカスタマイズし、パネルと通常詳細ページに同じ本文を表示する。

根拠は公式READMEとKaTeXオプション。互換性と数式記法は実装前に確認する。KaTeXのHTML機能を生Markdown HTMLの許可と混同しない。CSS・フォントは依存として同梱し、CDNへの依存を初版に追加しない。登録レビューで未対応数式を確認し、実行時に失敗しても演習の評価入力を消さない。

## 画像と配信

上限は5MiBと1600万画素を提案。形式・寸法・ファイルの内容を検証してから取り込む。content hashで配信用ファイルを識別し、ローカル原本パスを含まないURLをDB本文へ保存する。Next.jsのログイン済み画像中継→FastAPIの認証付き画像APIを使う案。認証無しのpublicフォルダーへ置かない。URLにトークンを付けない。ユーザー依存の応答を共有キャッシュに入れない。

画像はDBには入れず管理ディレクトリへ保存し、DBバックアップと対応する画像を一緒に保管する。登録・画像取り込みの中途失敗で参照切れを防ぐ処理と未参照画像回収はCLI詳細で決める。構成案はローカル向けで、本番ストレージや配信元は未選定。

## 通信とページング

中継timeoutは10秒の提案値。タイムアウトは保存失敗の証明ではないため、操作ID・演習IDを保持し同じ操作で確認・再送する。更新を新IDで再実行しない。APIが処理を終える前に中継接続が切れてもDBの原子性を維持する。

一覧は既定20、最大50件。知識・試験は表示順キーとID、履歴はsubmitted_at降順とIDで安定した順を持つ。キーセットカーソルは最後のキー・ID・フィルターを表す不透明な形式とし、型・サイズ・同じ対象フィルターでの利用を検証する。カーソルは認証・所有者確認の代わりにしない。フィルター変更時は先頭から取得する。具体JSONと文字列符号化は実装時に契約へ追記する。

## 設定と鍵

ローカルではプロジェクトの非追跡設定ファイルと、非追跡の鍵ディレクトリを使用する提案。Composeから設定・鍵を必要なサービスへだけ渡し、署名秘密鍵はWebだけ、公開鍵はAPIに読み取り専用で渡す。認証シークレット・Google秘密情報・DBパスワードをログやDockerイメージに含めない。`.env.example` などの雛形は実装開始後に値を空欄で作る。

ブラウザー公開のNEXT_PUBLIC系設定に秘密を入れない。ローカルのポートはWeb3000・API8000・DB5432を候補とし、衝突時は設定で変更する。実際にポートを開いたり既存サービスを停止したりしない。API・DBはローカル開発で必要な場合のみホストへ出す。本番公開やドメイン・Google callback URLは対象環境選定後に決める。

## 残る運用判断

登録データと根拠記録のGit追跡・公開範囲、アプリをローカル以外で使う段階とホスティング、退会・学習データ削除と研究用記録の保持、バックアップと復元の運用は別途確認が必要。今回の設定案で許可済み扱いにしない。
