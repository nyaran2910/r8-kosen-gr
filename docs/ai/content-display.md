# 本文表示と知識ナビゲーションの詳細案

[表示方針](../common/content-display.md) はユーザー確認済み。実装しない。

## 描画

共通Markdownレンダラーに内部リンク・画像・数式・表の表示ルールを組み込む。ユーザーにライブラリの技術仕様を見せない。生HTMLは無効、危険なURLスキームは許可しない。TeXのtrusted HTML機能も有効にしない。長い数式・表の横スクロールでページ全体のレイアウトを崩さない。対応数式の範囲は抽出例と独自問題で確認する。

ライブラリは後で公式資料を確認して選定する。今回具体名・バージョンを確定しない。共通表示部品は閲覧用のみで編集機能を増やさない。登録時の数式チェックと実際の表示チェックを別の確認項目にする。

## パネルの状態

演習内ではパネルに現在知識IDと知識IDの履歴を保持する。知識A→B→Aの循環参照も閲覧として許容する。学習の前提を自動推論しない。パネル内の戻る操作とブラウザーの戻る操作を混同させず、演習IDは維持する。深い参照の履歴はクライアントで管理し、ページ再読み込み後のパネル履歴・スクロール位置の完全復元は初版では保証しない。評価下書きと解答表示状態の復元は承認済み方針どおり行う。

パネルはキーボードでも開閉でき、閉じたら元リンクにフォーカスを戻す。読み込み中・404・通信失敗でも演習の評価入力を消さない。別ユーザーへの切替でパネルと個人理解度のキャッシュを破棄する。手動理解度の保存と演習評価の増減は現在状態の競合制御・確定時ルールを使う。

## 画像

配信用画像は登録済みの許可形式に限定し、ファイルの拡張子だけでなく内容も検証する設計。content hash等の安定した配信パスへ変換する案。DB本文に相対ローカルパスを残さず、配信パスに変換する。取り込み成功・レビュー・DB登録の整合性とロールバック後の未参照画像回収はCLIの設計時に具体化する。

画像配信はログイン済み利用者だけを対象にする案で、Next.js publicディレクトリへ無条件に置かない。FastAPIの認証付き配信をNext.jsが中継するなどの方式を画像APIで詰める。教材取得APIと同様、認証情報を画像URLへ入れない。画像のbyte数・pixel数の上限は後続で提案する。

## 残る設計

表示方針の確認後、ライブラリ・画像制限・鍵と設定の配置・タイムアウトとページングを技術設定の一まとまりとして具体化する。実装開始は別の明示指示が必要。登録データ・レビュー記録の公開範囲も未決定のまま。
