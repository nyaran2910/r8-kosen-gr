# 受け入れ確認の詳細

[3項目の手順](../common/acceptance-check.md) はユーザー確認済み。今回は手順だけを作成し、テストコード・データ・環境・アカウントは作らない。

意味のある検証は、認証署名と主体照合、未評価と初回計算、再送・同時保存、退会競合、復習境界、登録の原子性、画像とDBの復元整合を中心にする。UI表示だけで内部の二重更新がないと断定せず、確認環境の履歴・状態行を併せて調べる。

Google実ログイン・Cookie・同一オリジン中継は画面で確認する。認証拒否・JWT期限・別ユーザーのIDはAPI検証、表示開始通知と演習再開は画面とAPIを組み合わせる。日時指定・同時処理は専用試験で再現し、本番コードに一般利用者が時刻や所有者を指定する入口を追加しない。

検証結果は環境・版・対象仕様・成功または失敗・再現方法を記録し、秘密値・Googleトークン・個人学習履歴を共有ログへ載せない。不具合があれば修正後に関係する検証を繰り返し、変更がなければ同じ検証を無意味に増やさない。

初期3問で同じ形式しかないため、形式順位・複数ジャンルはテスト専用の定義と問題で確認する。初期5知識へ無理に他ジャンル所属を加えない。原本の取得元や利用条件の未確認事項は、検証成功とは別に保留する。

実装前設計はここで完成条件の具体手順まで一巡した。公開範囲・資料条件・実際のAI学習利用などは該当行為前の確認事項として残し、未確定のために新規機能提案を続けない。次の「はい」は今回手順の承認で、実装開始には明示指示が必要。
