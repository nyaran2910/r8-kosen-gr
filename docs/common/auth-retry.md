# ログイン通知・退会競合・再試行の案

ログイン通知・退会競合・期限切れ再試行の3項目はユーザー確認済み。実装・DB変更は行わない。

## 1. ログイン通知の再送

Googleログインが成功した一回ごとに操作IDを作り、Next.jsからAPIへ登録・ログイン完了を通知する。通知は最大60秒の期限付き署名で渡し、通常の学習API用トークンとは用途を分ける。

APIは操作IDと返した内部ユーザーIDを記録する。同じ通知の再送なら同じユーザーを返し、二つのアカウントを作らない。ただし、そのユーザーが退会済みなら再送を拒否し、Google紐づけを復活させない。

| 新しい記録テーブル案 | 内容 |
| --- | --- |
| login_registrations | 操作ID、内部ユーザーID、通知の発行日時、有効期限 |

Google識別子やトークン本体はこの記録に保存しない。期限切れの通知は、新しいアカウントを作る要求として扱わない。

## 2. 退会と保存の競合

同じユーザーの退会処理と評価・手動変更を順番に処理する。退会が先に確定したら、後から届いた保存は拒否する。評価保存が先に確定した場合、その評価を含めて学習データを保持する。

別端末の古いセッションも内部IDとGoogle識別子の一致で拒否する。再登録した新しいIDへ古い要求を付け替えない。

退会の返事だけ届かなかった場合、同じ退会操作を再送して完了を確認できるようにする。再送でユーザーや学習データを作り直さない。

## 3. 期限切れ・通信失敗の再試行

- 有効期限内のログイン通知は同じ操作IDで再送する。
- 期限を超えたらGoogleログインをやり直す。古い通知の期限を勝手に延ばさない。
- API用トークンだけが期限切れなら、Webセッションを確認してトークンを再発行し、同じ演習・操作IDで一回再試行する。
- Webセッションも切れていたら再ログインを案内し、ログイン復帰だけで新しい演習を作らない。

別の理由による認証拒否まで自動再試行し続けない。退会済みの旧セッションには再ログインが必要な旨を表示する。再ログインで新規登録した場合は旧演習を引き継がない。
