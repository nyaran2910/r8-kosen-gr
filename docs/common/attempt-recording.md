# 演習の計測・保存・再送の詳細案

計測・復習結果の履歴保存・手動変更の再送識別はユーザー確認済み。実装は行わない。

## 回答時間の記録

問題を取得しただけでは計測を始めず、画面に表示した直後に「開始通知」を送る。サーバーが最初の通知を受けた日時を `started_at` にする案。

「答えを見る」の操作でも直ちに通知し、サーバーの初回受信日時を `answer_viewed_at` にする。回答時間はこの二つの差。解答の取得待ち・解説閲覧・評価入力を含めず、中断・離席は含む。

初版では通信遅延による誤差を許容する。端末時計の変更の影響を避けるため、利用者の端末時刻をそのまま保存しない。開始通知を確認できるまでは解答表示を操作できない。再読み込みや再送で日時は上書きしない。

開始通知前の演習は `started_at=NULL` として予約状態にする案。既存の必須カラムを変更するため、今回確認してからDBへ反映する。

## 復習計算の結果を履歴に残す

`attempts` に、評価確定時に計算した次回復習日時と計算方式・版も保存する案。

| 追加項目 | 内容 |
| --- | --- |
| scheduled_review_at | その演習の確定で計算した復習日時 |
| scheduler_version | その計算に使った方式と版 |

未確定はNULL。確定後は変更しない。現在の予定は引き続き `user_problem_review_states` に保存する。

後から別の演習で予定が変わっても、保存結果の再送と履歴では当時の計算結果を返せる。将来の忘却曲線への変更後も、当時の予定を再計算しなくて済む。

## 手動変更の再送

手動の理解度変更ごとに操作IDを付け、変更履歴のIDとして使う案。同じ操作IDの再送は同じ結果を返し、新しい変更を重ねない。違う内容で同じ操作IDを使ったら競合として拒否する。

表示時の更新日時による競合確認も維持する。別の操作で値が変わっていたら、再取得してから変更する。

同じ値を指定した場合も、その操作を受け付けた記録を残す案。理解度・最終更新日時は変えず、再送時に以前の操作だと判別できるようにする。

この案では変更履歴に操作時の期待更新日時を追加し、再送内容を照合する。具体的なカラムと制約は [詳細コンテキスト](../ai/attempt-recording.md) に記録する。

## 通信が途中で切れた場合

演習開始・解答表示・評価保存・終了・手動変更は、同じ操作として再試行する。保存結果が不明なまま新しい演習や別の手動変更を始めない。

通信失敗・再試行中を画面に表示し、再ログインが必要なら同じ演習へ戻る。ログアウト時に評価の下書きを消す既存方針は維持する。
