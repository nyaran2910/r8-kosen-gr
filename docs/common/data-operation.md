# 初期データと変更・登録の運用案

初期範囲・登録・変更運用はユーザー確認済み。実装・実データの作成や登録は行わない。

## 最初に用意する範囲

対象試験は「東北大学工学部編入・数学」。まず既存の抽出例を使い、線形代数の知識5要素と「複数小問・計算中心」の形式から始める。試験区分は編入学。

初回確認用の自作・生成大問は3問を提案する。未評価・苦手・復習を確認できるよう、使用する知識の組み合わせを変える。その後に東北大の他の大問へ範囲を広げる。原本問題の全文は問題キャッシュに登録しない。コストは未設定のまま、コスト制限を使う生成は行わない。

## 登録とレビュー

- 初版は管理画面を作らず、構造化したファイルを人が確認し、CLIで登録する案。
- 定義・関連はJSON、知識本文・問題・解答・解説はMarkdownファイルとして編集し、登録時にDBのTEXTへ取り込む。
- レビュー前の候補はDBへ登録しない。登録前に数式・解答、知識の紐づけ、元資料の表現を持ち込んでいないか確認する。
- ファイルに安定IDを割り当て、同じデータの再登録では複製しない。登録対象・差分を事前表示してから反映する。

## 抽出根拠の記録

原本の識別子・ファイル参照、取得元と取得方法、抽出対象、作成方法、レビュー結果、登録先のIDをレビュー用ファイルに記録する。分からない項目は未確認とし、仮の取得元を補わない。

初版は出典テーブルを増やさず、登録データと対応する記録ファイルを維持する案。原文を根拠記録へ丸ごと複製しない。AI向けディレクトリに置くだけでは非公開にならないため、公開範囲は別途判断する。

## 訂正・廃止

| 対象 | 扱い |
| --- | --- |
| 問題 | 登録後の訂正は別IDの問題として保存。旧問題は廃止して新規出題を止め、過去の履歴は残す |
| 知識・形式・ジャンル | 誤字・表示の修正は同じIDで更新。学習対象の意味や分類が変わる場合は別IDにする |
| 廃止問題の演習 | 新規開始・解き直しは不可。既に開始した演習は継続・評価可能とする案 |
| 廃止問題の復習予定 | 保持するが、自動出題の候補から外す |

初版では問題に `retired_at`（廃止日時、未廃止はNULL）を追加する案。新しい定義へ過去の理解度を自動で移し替えない。定義本文の全バージョンをDBに保存する仕組みは初版では保留し、変更経緯を記録ファイルに残す。

## 理解度の手動変更

現在値の更新と一緒に、ユーザー・対象知識または試験形式・変更前後・変更日時を `understanding_changes` に記録する案。初めて手動設定した場合の変更前はNULL。演習評価の履歴とは分ける。

手動変更だけでは復習予定を変更しない。履歴は初版では記録を優先し、専用の変更履歴画面は設けない。誤設定は再度手動変更して直す。

運用方針は確認済み。現在は [登録ファイル・知識リンク・レビュー記録の案](data-format.md) を確認する段階。
