# 初版の範囲・工程・保留事項

初版の範囲・工程・保留事項の3項目はユーザー確認済み。実装開始の指示とは別に扱う。

## 1. 初版の範囲

DB・API・フロントをローカル起動し、Googleログインから学習・評価・復習・履歴確認まで一巡できるアプリにする。

- 対象は東北大学工学部編入・数学。最初の動作確認データは線形代数5知識と独自の大問3問。
- 試験選択・ホーム、演習、知識と形式の閲覧・理解度変更、履歴、ログアウトと退会を含む。
- 大問単位で自己評価。知識は要素ごと、形式は試験ごとに理解度を保持する。
- 中断再開・評価再送・候補なし・期限切れ・同時変更の競合も正常な画面の動作として扱う。
- 退会でGoogle紐づけを外すが、内部IDと学習データは残す。再登録は別ID。
- レビュー済みデータのファイル登録、問題廃止、バックアップと退会台帳も含む。

一般公開・リアルタイムAI生成・自動採点・学習データ削除・AI学習処理は初版に含めない。研究実験の効果測定は、アプリ完成とは別に計画する。

## 2. 実装の作業単位

実装開始の指示を受けた後、次の順で進める案。各段階の結果をまとめてレビューし、カラム・ファイル一つずつの確認には戻さない。

| 段階 | 作るもの | 確認できる結果 |
| --- | --- | --- |
| 1. ローカル基盤 | Web・API・DBの構成と起動設定 | 三つが起動し、接続と設定不足が確認できる |
| 2. DB・認証 | 確認済みテーブル、Googleログイン、署名JWT、退会時の認証拒否 | ユーザーが分離され、旧ログインから再登録や復活をしない |
| 3. 登録・閲覧 | JSON/Markdown登録、初期データ、本文・画像・知識リンク | 3問と5知識をログイン後に閲覧できる |
| 4. 学習の一巡 | 演習開始・解答表示・評価保存・理解度更新・履歴・手動変更 | 一回の学習と中断再開、再送・競合を確認できる |
| 5. 出題・運用 | 復習と弱点の選択、退会台帳、バックアップ・復元 | 初版の完成条件を一通り確認できる |

途中でユーザーの操作やデータ保持の方針を変える必要が出た場合はまとめて確認する。設定名や内部関数など通常の実装判断はその段階で扱う。

## 3. 保留事項と確認する時期

| 項目 | 確認する時期 |
| --- | --- |
| Google Cloudのクライアント設定・ローカルのcallback URL | 認証を接続する前。設定値を用意する手順をまとめて案内 |
| 登録通知の再送・退会後の遅延通知拒否 | DB・認証実装の前に内部契約を仕上げる |
| 依存の版・正式JSONスキーマ・保存先・鍵配置 | 各段階の着手時に互換性・環境と合わせて具体化 |
| 原本の取得元・利用条件・解答解説の作成方法 | 該当資料の入力・公開・配信前。未確認を許可済みにしない |
| コード・原本・登録データ・根拠記録の公開範囲 | Git追跡・公開変更を行う前 |
| コスト算出・制限、忘却曲線、AI生成・pgvector | 初版後の拡張を始める前 |
| 保持データのAI学習・研究利用、保持期間や説明 | 実際の二次利用・実験を始める前 |
| 別媒体へのバックアップ・ホスティング | ローカル開発を越えて実利用する前 |

未決定事項があることを理由に機能を追加し続けず、該当段階で具体化する。設計確認が済んでも、実装開始の指示があるまでは文書作業に留める。
