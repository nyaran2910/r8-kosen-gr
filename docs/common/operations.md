# 初版の公開・削除・バックアップ運用案

ローカル起動と退会後の学習データ保持は確認済み。公開範囲は確認前。バックアップ・退会台帳・完成条件は確認済み。実装・設定変更・削除・バックアップは行わない。

## 利用する場所と公開範囲

初版はDB・API・フロントエンドを全て開発者のPCでローカル起動する。学習者へ使ってもらう段階で、公開先・URL・実験用の説明を別途決める。Googleアカウントがあれば利用できる方針は維持するが、この段階ではインターネットへ公開しない。

| 対象 | 初版の案 |
| --- | --- |
| コード・一般的な設計文書 | 公開候補。既存リポジトリの公開状態は変更しない |
| 原本・取得元の記録・レビュー記録 | 非公開で管理する方針を提案。既存Git履歴への対応は別途確認 |
| 独自記述の定義・自作問題 | アプリ内で提供。Gitでの公開は別途判断 |
| 利用者の学習データ・バックアップ | 非公開。Gitへ入れない |
| 認証シークレット・秘密鍵 | 非公開。Gitへ入れない |

ディレクトリ名やgitignoreだけで、既に公開した内容が非公開になるわけではない。今回の案で既存ファイルの移動・削除・Git履歴変更は行わない。

## アカウント削除と学習データの保持（確認済み）

- 学習データを削除するリセット機能は初版に設けない。
- アカウント削除ではGoogleアカウントとの紐づけ・保存している認証情報を除去し、ログアウトする。
- アプリ内のユーザーIDと、それに紐づく理解度・演習履歴・手動変更履歴・復習予定は保持する。
- `users.google_sub` をNULLにし、`users.id` は残す。Googleアカウント自体は削除しない。
- 古いセッションから保持した学習データを利用・更新できないようにする。

同じGoogleアカウントで再登録した場合は新しい内部IDを作り、旧データを自動で引き継がない（確認済み）。

## 再登録・古いセッションの扱い（確認済み）

1. 初回・再登録は、Googleログイン完了時にだけ行う。通常のAPIアクセスでユーザーを自動作成しない。
2. ログイン情報にはGoogle識別子と内部ユーザーIDを持たせ、APIで両方の一致を確認する。
3. 退会時はGoogle識別子を外す。別端末に残った古いログイン情報でも、その内部IDの認証紐づけがないためアクセスを拒否する。
4. 同じGoogleで再登録した場合は新しい内部IDを作る。旧IDの学習データは保持し、本人へ自動で引き継がない。

退会は設定画面から実行前に確認し、「Googleとの紐づけは削除するが学習データは保持する」と表示する。退会処理と学習データの更新が競合しないよう制御し、退会後の遅延した評価保存は拒否する。

Google側のアプリ利用許可まで取り消す処理は初版に設けず、アプリ内の紐づけ解除・ログアウトを行う案。必要ならGoogle側で許可を取り消す操作を別途案内する。

## 将来の利用

保持した学習データを将来のAI学習・研究へ使えるようにしておく方針。ただし初版で外部への送信・モデル学習・研究用エクスポートは実装しない。

実際に利用する前に、対象データ・利用者への説明・利用条件・保持期間を具体化する。Googleとの紐づけを外しただけで、履歴が匿名化済みだとは扱わない。退会画面にも、認証情報を外すことと学習データは保持することを分けて表示する。

## バックアップ

開発中は教材登録・DB変更の前に、DBと配信用画像を対応づけて保存する案。直近7世代を保持し、実データを使う段階では1日1回も追加する。復元は別の確認用DBで試す。

過去のバックアップにGoogleとの紐づけが残る場合がある。復元時に退会済みの認証紐づけを戻さないため、退会記録を別途管理する案。学習データは復元対象として保持する。7世代保存と退会台帳の基本構成は確認済み。具体的な保存先は環境構築時に決める。詳細は [ローカル運用](local-operation-review.md)。
