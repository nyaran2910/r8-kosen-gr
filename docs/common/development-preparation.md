# 着手準備の3項目

配置・設定・初期3問の検証内容はユーザー確認済み。ディレクトリ・設定・実問題・コードは作らない。

## 1. コードの配置

```text
apps/web/              # Next.js。画面・認証・API中継
apps/api/app/
  api/                 # FastAPIのHTTP入口
  models/              # DBモデル
  schemas/             # 入出力型
  services/            # 評価保存・復習計算・出題選択
  cli/                 # 登録・バックアップ・退会台帳の運用
apps/api/migrations/   # Alembic
apps/api/tests/        # APIと処理の検証
apps/web/tests/        # Web側の検証
assets/curated/          # レビュー対象の定義・独自問題
assets/reviews/          # 根拠・レビュー記録
compose.yaml           # ローカル起動
```

DBアクセスや評価処理はAPI側に集める。Web側に同じ理解度更新ロジックを二重実装しない。画像の保存領域・秘密鍵・バックアップ・退会台帳はこのコード配置と別にする。データのGit追跡と公開範囲は決めず、実ファイル作成前に確認する。

## 2. 接続先と設定

| 設定 | 案 |
| --- | --- |
| ブラウザーで開くURL | `http://localhost:3000` |
| API | Compose内部の `http://api:8000`。ブラウザーからはNext.js経由 |
| DB | Compose内部の `db:5432`。最初はホストへ公開しない |
| Googleログインの戻り先 | `http://localhost:3000/api/auth/callback/google` |
| Google設定 | `AUTH_GOOGLE_ID` と `AUTH_GOOGLE_SECRET` |
| Webセッション暗号化 | `AUTH_SECRET` |
| API用署名 | Webに秘密鍵のファイル参照、APIに公開鍵のファイル参照 |

必要設定が不足していたら、項目名を示して起動・ログインを止める。適当な秘密値で動作を続けない。コードに秘密を直書きせず、雛形は空欄で作る。開発者向けにAPIを直接確認する必要がある場合だけ、localhost限定でポートを開く。

Auth.jsのcallbackパスとGoogle設定名は [公式資料](https://authjs.dev/getting-started/providers/google) に合わせた案。ポートを変える場合は戻り先の設定も合わせる。Google Cloudの実設定は認証着手時にまとめて案内する。

## 3. 最初の3問と検証する動作

| 独自の大問 | 使用知識の組み合わせ案 | 主な確認 |
| --- | --- | --- |
| A | 固有値・固有ベクトル・正規化 | 初回評価、3知識分の必須入力、リンク閲覧 |
| B | 固有値・固有ベクトル・対角化 | Aと共有する知識の理解度更新、別知識の未評価 |
| C | 対角化・行列の累乗 | 苦手知識の優先、既存状態と新規状態の混在 |

いずれも線形代数・複数小問・計算中心の新しい問題として作る案。具体的な行列・設問・解答は後で独自作問し、レビュー前に登録しない。

この3問だけでは複数ジャンル・複数形式の順位差を確認できないため、それらはテスト専用の仮データで検証する。複数ジャンルを実問題で組み合わせることを、初期データ3問の必須条件にしない。

未評価・理解度1と5・再送・退会などの状態は、テスト用ユーザーと仮データで作る。実利用者の履歴を検証のために書き換えない。
