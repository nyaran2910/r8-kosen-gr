# 初版の受け入れ確認手順

起動登録・認証退会・学習復習の受け入れ確認手順はユーザー確認済み。コードやテストデータはまだ作らず、試験を実行した記録とも区別する。

## 1. 起動・登録・復元

1. 新しい確認環境でDB・API・Webをローカル起動する。設定不足は項目名で確認でき、秘密値は表示されない。
2. 未承認データ・不正参照・承認後に本文を変えたデータの登録が止まり、DBに一部分も入らない。
3. 承認済みの5知識・3問を登録し、同じ登録の再実行で件数が増えない。
4. 数式・表・画像・知識リンクを表示でき、原本の問題や画像が配信対象に入っていない。
5. DBと画像をバックアップし、別の確認環境へ復元する。退会台帳を照合した後にログインを有効にし、画像・履歴・認証紐づけの状態を確認する。

## 2. 認証・退会・再登録

1. テスト用のGoogleアカウントA・Bでログインし、学習状態が分離される。
2. BがAの演習IDを指定しても閲覧・解答取得・評価・終了ができない。
3. ログイン通知を再送してもユーザーを重複作成しない。期限切れ・署名不正の通知を拒否する。
4. Aが退会するとGoogle紐づけだけが外れ、内部IDと学習データは残る。別端末の旧セッションから更新できない。
5. 退会と評価保存の両順序を確認する。退会後の保存は拒否し、保存済みの履歴は保持する。
6. Aが再登録すると新ID・未評価状態になり、旧IDの学習データを引き継がない。

## 3. 学習・理解度・出題

1. 演習を開き、知識パネルを辿って戻る。再読み込みでも同じ演習・開始時刻・解答表示状態を維持する。
2. 全知識の評価が揃うまで確定できない。初回「わかった」は4、「わからない」は2、形式の初回「完璧」は5になる。
3. 理解度1・5での増減が範囲を超えず、評価再送でも二重更新しない。確定後の違う評価は拒否する。
4. 手動変更で現在値と変更履歴だけが更新され、過去演習や復習予定は変わらない。別タブとの競合を検出する。
5. 復習日時の直前は自動出題候補外、ちょうど72時間で候補になる。期限到達した復習を先に、残りは確認済みの知識・形式の順位で選ぶ。
6. 候補なし、手動解き直し、中断演習の終了、廃止問題の出題停止を確認する。履歴を見るだけでは演習や予定を更新しない。

復習時刻・通信失敗・同時処理は確認環境の専用データで再現し、実利用者のデータを書き換えない。各段階で該当する確認を実施し、最後に学習の一巡と復元を通して確認する。

この手順の承認は、実装・Google設定・データ作成の開始指示とは別。次に機能を増やさず、設計の確認状況を締める。
