# 登録ファイル・知識リンク・レビュー記録の案

登録ファイル構成・知識リンク・根拠とレビュー記録の形式はユーザー確認済み。以下は設計例。ディレクトリ・実データ・登録コードは作成しない。

## ファイル構成

```text
assets/
  curated/<登録単位>/
    manifest.json       # 定義・関連・本文ファイルへの参照
    knowledge/<ID>.md   # 知識本文
    problems/<ID>/
      body.md           # 大問の問題文
      answer.md         # 解答
      explanation.md    # 解説
    images/             # 独自作成など利用条件を確認した画像
  reviews/<登録単位>/
    provenance.json     # 原本参照・抽出と作成の根拠
    review.json         # レビュー結果・対象データの識別
```

登録単位は「最初の線形代数」のようなまとまり。共有する知識は一つの登録単位で定義し、他の単位からIDで参照する。公開範囲・Gitへの追加は別途判断し、この案でファイル公開を決めない。

## JSONに入れるもの

`manifest.json` に形式の版 `schema_version`、登録単位ID `bundle_id`、教科・試験・ジャンル・形式・知識・問題と、それらの関連を持たせる。

知識レコードは `id`・`genre_id`・`title`・`body_file`・`cost`。問題レコードは `id`・`exam_id`・`format_id`・`body_file`・`answer_file`・`explanation_file`・`retired_at`。本文参照はmanifestからの相対パスとし、登録時に読み込んでDBの本文カラムへ保存する。

IDはUUIDで固定し、本文の名称変更やファイル移動で作り直さない。コスト未設定・未廃止はJSONの `null` を使う。知識の使用順は本文で説明し、紐づけのJSON配列順に意味を持たせない。

## 知識リンク・数式・画像

知識へのリンクは、Markdownのリンク先をアプリ内の固定パスにする案。

```markdown
[固有値](/knowledge/11111111-1111-4111-8111-111111111111)
```

表示する名前と参照するIDを分ける。アプリはこのリンクから知識詳細を開き、演習へ戻れるようにする。ファイル名やタイトルでは紐づけない。

数式は `$...$` と `$$...$$`。画像は本文ファイルからの相対参照とし、登録時に配信用の参照へ変換する。原本ファイルやローカルの絶対パスはアプリへ配信しない。

本文中の知識リンクと `problem_knowledge` は別。参考としてリンクしただけの知識を、必須評価・コスト計算の対象へ自動追加しない。

## 根拠・レビュー

- `provenance.json`：原本識別子、取得元・方法、原本の位置、抽出・独自記述・生成の方法、対応する登録先ID。未確認項目は `null` と確認事項で残す。
- `review.json`：登録単位ID、レビュー者・日時、結果（pending／approved／rejected）、確認事項、確認したファイルのハッシュ。
- 原本本文を複製せず、参照だけを記録する。手動作問の場合も実際の作成方法を記録する。
- 承認した後にJSON・本文・画像・根拠記録が変われば再レビューする。同じ承認を使い回さない。

登録前に本文・リンク・参照ID・紐づけ・レビュー済みの内容との一致を確認する。登録済みIDと違う内容は差分を示し、問題を自動上書きしない。
