# ローカル初版の運用・完成条件の確認案

バックアップ・退会記録・初版完成条件の3項目はユーザー確認済み。実装・保存先作成・バックアップ・復元は行わない。

## 1. バックアップ

| 項目 | 案 |
| --- | --- |
| 保存対象 | PostgreSQLのDB、配信用画像、登録データ・レビュー記録の識別情報 |
| 保存タイミング | 教材登録・DB変更の前。利用した日は終了時にも保存 |
| 保存数 | 直近7世代 |
| 保存場所 | リポジトリ外のローカル保存先。Gitには入れない |
| 復元確認 | 別の確認用DBと画像領域へ復元し、現在のデータを上書きしない |

DBと画像を同じ保存単位で対応づける。認証秘密鍵やGoogleの秘密情報はDBバックアップへ混ぜない。保存先の具体的なパスは環境構築時に決める。

同じPC内の保存なので、PCの故障・紛失への対策まではできない。初版のローカル確認用とし、実験で本格利用する前に別媒体への保存を決める。

## 2. 退会済みの認証情報を復活させない記録

古いバックアップのDBには退会前の `google_sub` が残る場合がある。そのまま復元してログイン可能にしないため、退会記録を別に保持する案。

| 項目 | 案 |
| --- | --- |
| 記録する情報 | 退会した内部ユーザーID、退会日時、処理を識別するID |
| 記録しない情報 | Google識別子・メールアドレス・秘密情報 |
| 保存先 | 非公開のローカル退会台帳。DB復元とは別に維持 |
| 復元時の処理 | 台帳と照合し、該当ユーザーのGoogle紐づけを再度NULLにする |
| 学習データ | 台帳照合でも削除しない |

復元後の照合が終わるまでログイン・API利用を開始しない。台帳は退会済みか判断する運用記録で、学習データを消すためのものではない。

バックアップの保存世代から独立して、保持ユーザーがいる間は退会記録を残す。実行途中に落ちても「紐づけは消えたが台帳に残っていない」を防ぐ処理は詳細文書で設計する。

## 3. 初版の完成条件

実装後、次を一通り確認できたらローカル初版の完成とする案。

1. DB・API・フロントを全てローカルで起動できる。
2. Googleログインでユーザーを作り、別ユーザーの学習データへアクセスできない。
3. 知識5要素・自作問題3問で、問題→解答→知識→評価→履歴の一巡ができる。
4. 中断・再読み込み・通信失敗の再送で、演習が増えたり理解度が二重更新されたりしない。
5. 未評価・苦手・復習の出題ルールと、72時間の境界を日時指定で確認できる。実際に3日待つ必要はない。
6. 手動理解度変更、問題廃止、退会後の学習保持・旧セッション拒否・新IDでの再登録が動く。
7. バックアップを別DBへ復元し、画像が表示でき、退会済みのGoogle紐づけが復活しない。

初版では外部公開・AI自動生成・コスト制限付き生成・忘却曲線モデル・AI学習用のデータ利用は完成条件に含めない。
